valid for the latency comparison; the statuses in this table are not
comparable to full-run statuses and are shown only as recorded. Authoritative
per-sample statuses are in the full runs (docs/logs/step13-t5-parity.txt).

container start), so Coraza audits are not exposed to the reload race.

Affected tables (ModSecurity audit-derived): rule-presence tables and
rule-ID listings on non-blocked samples derived from the audits of the runs
marked "not checked" — in particular the step-11 WCP rule-presence tables,
the step-12 matched-shape probe rule comparison (920260), the step-12
oversize/sizeprobe rule attributions, the step-12 cookie-restored rule-ID
tables, and the ModSecurity side of docs/logs/step13-t5-rule-presence.txt
(built from step-12 ModSecurity audits). These are marked "completeness
unproven" in docs/baseline-v0.9.md. Blocked-set / status / worst-case
comparisons are based on HTTP responses and are NOT affected. Per-sample rule
IDs read from entries that ARE present in an audit remain valid (the race
loses whole entries, it does not corrupt present ones); only totals from
those audits are "completeness unproven".
